## API Contract Rules
For generic crypto APIs:
- /api/crypto-price must validate allowed symbols
- /api/crypto-klines must validate allowed symbols and timeframes
- responses must include provider, symbol, and updated_at where applicable
- error responses must be structured and non-secret
For legacy APIs:
- /api/btc-price must remain backward-compatible
- /api/btc-klines must remain backward-compatible
- do not break old Zenora provider-health consumers
For provider health:
- /api/provider-health should be lightweight and safe
- /api/provider-health/deep may be heavier but must not leak secrets
- health output must be client-safe
For Tifa APIs:
- /api/tifa and /api/tifa/stream must preserve chat/SSE contracts
- SSE events must remain stable
- sanitized provider errors only
- no Gemini API key leakage
- no auth token leakage
For Tifa tools:
- only allowlisted tools may execute
- no dynamic external URL execution from user input
- tool failures should be warnings when partial context is safe
- orchestration must degrade gracefully

## Safe Git Operations
Allowed when scope is small:
- git status --short
- git diff -- <file>
- git add <file>
- git commit -m "type(scope): message"
- git push origin <branch>
Disallowed:
- git reset --hard
- git clean -fd
- git rebase -i
- git push --force
- broad multi-file refactors without an approved slice
- auth/security rewrites without explicit approval
Commit style:
- chore(devops): ...
- docs(...): ...
- fix(api): ...
- fix(ui): ...
- fix(tifa): ...
- test(...): ...
- refactor(...): ...
